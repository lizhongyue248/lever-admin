# 10 当前组织管理页

- 路由组：`/dashboard/orgs/[slug]`
- 目标：为组织 owner/admin 管理当前组织（公司）及其内部部门架构、邀请、登录情况和设置。

## 功能范围

当前组织管理页负责组织管理员对单个公司的治理操作。Better Auth 的 organization 表示公司或租户；公司内部的组织架构使用部门树表达，部门不是独立 organization，不拥有独立 slug，也不作为独立租户存在。

Better Auth organization plugin 负责基础 organization、member、invitation 和 active organization 能力；部门层级、部门成员归属、部门统计、树状展示和跨部门成员聚合属于产品层扩展。

普通成员访问时只展示允许查看的只读组织信息和权限不足状态；平台超级管理员如需跨平台治理，应使用 `15-dashboard-admin-orgs.md` 定义的平台组织管理页。

## 页面布局

- 整体布局继承 `06-dashboard.md` 的 DashboardLayout：
  - Sidebar、Topbar、左下角用户菜单、主题切换、面包屑与响应式行为均保持一致。
  - 本页只定义 Main 内容区域布局，不重复定义全局壳层。
- Sidebar：
  - 当前组织入口移动到「账号设置」分组内，作为个人资料、安全设置、我的会话之后的组织管理入口。
  - 不再单独展示「组织」分组，避免普通用户误以为存在独立组织中心。
  - 导航项之间使用更紧凑、均匀的垂直间距；分组标题与导航项保持 dashboard 统一的信息密度。
- Main 共享结构：
  - 内容区不展示额外页面标题、子标题或大号概览横幅。
  - 顶部只保留 tab 导航，不在 tab 工具条右侧放置创建或邀请动作。
  - tab 导航包含「概览」「组织架构」「邀请」「登录情况」「设置」。
  - tab 使用路由跳转，不使用 query 切换。
  - 「添加部门」按钮只在「组织架构」tab 的组织结构卡片标题行最右侧展示，使用图标按钮，悬停或聚焦时展示可访问说明。
  - 「邀请成员」按钮只在「邀请」tab 的搜索筛选卡片最右侧展示，使用图标按钮，悬停或聚焦时展示可访问说明。
  - 概览、登录情况和设置 tab 不展示这两个快捷动作。
  - 主内容卡片、统计卡片、表格容器和部门树容器使用轻微外阴影，保持和 dashboard 既有卡片风格一致。
  - 每个 tab 必须使用与自身布局一致的 loading 骨架，不允许所有子页面共用同一个概览式骨架：
    - 概览 loading：tab 下方展示统计卡片骨架、成员增长图表骨架和最近事件骨架。
    - 组织架构 loading：桌面端展示左侧 `1/3` 部门树骨架和右侧 `2/3` 成员表格骨架；移动端展示上方树卡片骨架和下方成员卡片骨架。
    - 邀请 loading：展示搜索筛选卡片骨架、邀请状态筛选骨架和邀请表格/移动卡片列表骨架。
    - 登录情况 loading：展示会话统计、筛选控件和成员登录设备表格/移动卡片骨架。
    - 设置 loading：展示组织信息表单骨架和危险区域动作骨架。
  - 共享的根级 loading 只保留 Dashboard 壳层内的最小兜底，不作为五个 tab 的最终骨架。
- `/dashboard/orgs/[slug]` 概览：
  - 作为公司治理统计页，展示当前公司整体统计、成员增长、安全覆盖、邀请处理、登录风险、部门治理和最近组织事件。
  - 成员增长图表必须来自 `auth_member.created_at` 的真实成员加入时间，默认展示最近 6 个月截至每月末的累计成员数；没有成员时展示 0 值趋势，不使用示例月份或固定假数据。
  - 成员增长图表使用 shadcn/ui Chart 与 Recharts 呈现，必须包含坐标轴、网格线和 tooltip，不使用手写 div 柱状图。
  - 不展示部门树节点管理区；部门树管理统一放在组织架构页。
- `/dashboard/orgs/[slug]/information` 组织架构：
  - 桌面端使用左右两栏布局。
  - 桌面端左侧组织结构树占内容区约 `1/3`，右侧成员列表占剩余约 `2/3`，两栏间距保持 dashboard 卡片间距一致。
  - 左栏使用真正的树节点 UI 表达公司内部部门结构，包含展开/折叠按钮、层级连接线、节点图标、成员数、邀请数和风险状态。
  - 树节点布局必须紧凑，节点行高约 `28px - 32px`，层级缩进约 `16px - 20px`，不使用大卡片式节点。
  - 树节点选中态使用整行浅色底和左侧强调色，普通节点只保留 hover/焦点底色和轻量图标。
  - 树节点可展开和折叠；默认展开当前组织和存在风险的分支。
  - 部门树节点支持右键菜单操作，不在树行内常驻编辑按钮，避免破坏紧凑树布局。
  - 右键菜单包含「重命名部门」和「删除部门」；公司根节点不允许删除，可禁用或隐藏删除项。
  - 重命名打开弹窗，填写部门名称并校验同级重名；删除必须二次确认，并明确删除后对下级部门、部门成员归属和统计的影响。
  - 右栏未选中部门节点时展示图片占位符和空状态说明。
  - 右栏选中公司根节点或部门节点后，展示该节点成员列表，包括成员、组织角色、所属部门、加入时间、最后登录时间、安全状态和操作。
  - 成员列表标题行右侧为平台超级管理员展示「新增用户」图标按钮；组织 owner/admin 不展示该入口。
  - 成员列表操作列包含分配部门和移除成员：
    - 右侧成员区的行内操作使用图标按钮，不使用文字按钮，图标需要有可访问标签和 tooltip。
    - 当成员「所属部门」为「未分配」时展示分配部门图标按钮，点击后打开分配部门弹窗。
    - 已分配成员不展示分配入口，避免第一版引入跨部门调整和多部门归属的歧义。
    - 移除成员使用移除或垃圾桶图标按钮，对有权限的管理员展示，点击后必须二次确认；移除的是当前公司成员身份，并同步清理其部门归属。
  - 新增用户弹窗仅平台超级管理员可用，支持输入邮箱后添加已存在平台用户，或在邮箱不存在时创建新平台账号并加入当前公司。
  - 新增用户弹窗包含邮箱、姓名（创建新账号时必填）、组织角色和初始部门（可选）；如果邮箱已属于当前公司，提交时展示冲突错误。
  - 成员列表支持搜索、角色筛选、分页和表格最大高度滚动。
  - 组织成员、邀请和登录情况的桌面表格使用共享 `DataTable`，基于 TanStack Table 渲染表头、行和单元格。
  - 组织成员、邀请和登录情况的分页控件使用共享 `DataPagination`；首页、上一页、下一页、末页为图标按钮，页码输入框支持输入后按 Enter 跳转。
  - 点击组织结构卡片右上角「添加部门」图标按钮后打开弹窗，不再展示占位 toast。
  - 添加部门弹窗默认把当前选中的部门节点作为上级部门；如果未选中部门，则默认添加到公司根节点下。
  - 添加部门弹窗包含上级部门只读显示、部门名称、部门负责人（可选）和部门说明（可选）；部门不填写 slug。
  - 添加部门成功后关闭弹窗、清空表单、展示成功 toast，并刷新部门树、概览统计和右侧成员区。
  - 添加部门失败时保留弹窗输入，并展示 tRPC 返回的错误 toast，例如同级部门重名、权限不足或上级部门不存在。
- `/dashboard/orgs/[slug]/invite` 邀请：
  - 展示邀请列表、邀请状态、目标部门、邀请角色、邀请人、过期时间和操作。
  - 邀请状态必须使用 badge 展示：待接受、已接受、已拒绝、已取消和已过期使用不同视觉状态。
  - 发送邀请成功后必须关闭弹窗、清空邮箱输入、展示成功 toast，并刷新邀请列表表格。
  - 发送邀请必须使用 Better Auth organization invitation 能力或与其语义完全一致的服务端封装，不允许仅手动插入 `auth_invitation` 而绕过过期时间、权限校验和邀请邮件回调。
  - 邀请创建成功后必须生成 `expiresAt`，默认遵循 Better Auth organization plugin 的邀请过期配置。
  - 邀请创建成功后必须触发邀请通知；邀请邮件通过 `src/server/service/email` 统一发送服务发送，开发环境可使用 `EMAIL_PROVIDER=console` 输出邀请 URL，生产环境使用 Resend 或 SMTP provider 发送接受链接。
  - 邀请链接指向 `10A-organization-invitation-accept.md` 定义的邀请接受页。
  - 被邀请用户会在 Dashboard Topbar 右侧通知图标中看到待处理邀请数量；打开通知面板后可直接接受或拒绝邀请。
  - 邀请通知项展示组织名称、默认部门（可选）、邀请角色、邀请人和过期时间；默认部门只作为加入后的内部归属展示。
  - 提供搜索、状态筛选、目标部门筛选、分页、取消邀请和重新发送邀请。
  - 搜索筛选卡片使用同一行承载搜索框、筛选控件和右侧邀请成员图标按钮；移动端可换行，但邀请按钮仍位于筛选卡片右上角。
- `/dashboard/orgs/[slug]/auth` 登录情况：
  - 展示当前公司范围内成员登录情况、活跃会话、异常位置、设备分布和会话撤销入口。
  - 支持按部门节点、成员、设备类型和风险状态筛选。
- `/dashboard/orgs/[slug]/setting` 设置：
  - 组织信息使用表单呈现，包含公司名称、slug、logo、组织 ID、创建时间和成员数量。
  - Logo 支持上传文件，上传走 `18-dashboard-admin-platform-settings.md` 中定义的统一文件存储配置；上传成功后把返回 URL 写入 `auth_organization.logo`。
  - Logo URL 输入保留为可选高级方式，便于使用外部公开图片。
  - 可编辑字段使用输入框、选择器或上传入口；只读字段使用禁用输入框或只读文本域，避免纯详情列表样式。
  - 表单底部展示保存按钮和重置按钮，保存成功后展示 toast。
  - 危险区域由多组危险动作组成，每个动作必须包含标题、影响说明和右侧按钮。
  - 危险区域按钮包括停用组织和删除组织；删除使用 destructive 样式，停用使用 outline destructive 或警示样式。
  - 删除组织前必须明确说明对部门、成员、邀请和会话的影响。
- 移动端：
  - tab 过长时不使用横向滚动，改为下拉菜单切换当前分区。
  - 下拉菜单按钮显示当前分区名称和向下箭头，展开后列出「概览」「组织架构」「邀请」「登录情况」「设置」。
  - 当前分区在下拉菜单中展示选中态；选择后通过对应路由跳转。
  - 移动端不在顶部 tab 区展示创建或邀请动作；组织架构和邀请动作仍分别放在对应内容卡片内。
  - 组织架构页改为上方部门树、下方成员列表；未选中节点时成员区展示空状态。
  - 密集表格改为成员卡片列表，分页按钮保持可见。
- 设计稿：
  - `prd/dashboard-org-design.pen` 需要包含当前组织五个 tab、组织架构未选中空态和平台组织管理页。
  - `prd/dashboard-org-design.pen` 需要包含当前组织五个 tab 的 loading 骨架状态，且骨架结构必须分别匹配各自页面布局。
  - 每个页面需要覆盖桌面明亮、桌面暗黑、移动明亮、移动暗黑四种画板。
  - 暗黑主题使用中性炭灰背景和低对比边框，不使用深蓝大面积底色。

## 切换方式

- tab 与路由一一对应：
  - `概览`：`/dashboard/orgs/[slug]`
  - `组织架构`：`/dashboard/orgs/[slug]/information`
  - `邀请`：`/dashboard/orgs/[slug]/invite`
  - `登录情况`：`/dashboard/orgs/[slug]/auth`
  - `设置`：`/dashboard/orgs/[slug]/setting`
- tab 导航使用链接跳转，刷新和分享 URL 时保持当前分区。
- 进入当前组织管理默认打开概览页。
- 从部门树、成员入口或平台组织卡片进入时可打开组织架构页。
- 从邀请提醒进入时打开邀请页。
- 旧路径 `/dashboard/orgs/[slug]/members` 不再实现业务页面，应重定向到 `/dashboard/orgs/[slug]/information`。

## 用户动作

- 查看当前组织治理概览。
- 在五个组织治理 tab 间切换。
- 添加部门。
  - 在组织架构 tab 中点击添加部门图标按钮。
  - 在弹窗中确认上级部门，填写部门名称、负责人（可选）和说明（可选）。
  - 提交后在部门树中看到新节点，并可继续选择该节点查看成员空态。
- 右键编辑部门。
  - 在组织架构 tab 的部门树节点上右键打开菜单。
  - 点击重命名后打开弹窗并保存新名称。
  - 点击删除后打开确认弹窗；根节点不可删除。
- 邀请成员加入当前组织，并可选指定默认部门。
  - 发送邀请后被邀请人通过邮件链接或 Dashboard Topbar 通知面板接受或拒绝邀请。
  - 若指定默认部门，被邀请用户接受后加入的是当前公司，默认部门仅作为公司内部初始归属。
  - 搜索、筛选和处理邀请。
- 查看树状部门结构。
- 选择公司根节点或部门节点。
- 查看选中部门节点的成员列表、加入时间和最后登录时间。
- 修改成员角色。
- 为未分配成员分配部门。
- 从当前公司移除成员。
- 平台超级管理员可将已有平台用户加入当前公司，或创建新账号并加入当前公司。
- 移除成员。
- 查看组织成员登录情况。
- 撤销成员异常会话，可选。
- 修改组织名称、logo 和 slug，可选。
- 删除或停用组织。

## 接口与逻辑

- `org.getBySlug`：读取组织详情，并校验当前用户为组织成员或平台管理员。
- `org.management.getOverview`：聚合公司成员数、部门数、邀请数、活跃会话、风险事项和最近事件。
- `org.department.list`：读取当前组织的部门树，返回部门节点层级、成员数、邀请数和风险状态；根节点代表公司本身，不是部门记录。风险状态必须由真实会话或请求日志计算，不允许固定返回 `0`。
- `org.department.create`：在当前组织内指定上级部门下创建部门；输入包含 `parentDepartmentId`、`name`、可选 `managerUserId` 和可选 `description`；服务端校验当前用户是组织 owner/admin 或平台管理员、上级部门属于当前组织、同级部门名称不重复。
- `org.department.rename`：重命名部门；服务端校验当前用户是组织 owner/admin 或平台管理员、部门属于当前组织、同级部门名称不重复。
- `org.department.delete`：删除部门；服务端校验当前用户是组织 owner/admin 或平台管理员、部门属于当前组织；根节点不是部门记录不能删除；删除前按实现策略处理子部门和部门成员归属。
- `org.department.move`：移动部门节点到新的上级部门，可选。
- `org.department.member.list`：读取公司根节点或指定部门节点的成员列表，支持搜索、角色筛选、安全状态筛选和分页。
- `org.department.member.assign`：将当前公司内未分配部门的成员分配到指定部门；服务端校验成员和部门都属于当前公司、操作者具备组织 owner/admin 或平台管理员权限，且成员当前没有部门归属。
- `org.invitation.list`：读取当前组织范围内邀请列表，支持状态、目标部门和分页筛选。
- `org.member.invite`：创建 invitation，并可选绑定默认部门；实现时应调用 Better Auth organization invitation API 或封装同等语义，必须生成过期时间、触发邀请通知、避免重复 pending 邀请造成歧义。
- `org.invitation.cancel`：取消 pending 邀请，校验当前用户具备组织邀请管理权限。
- `org.invitation.resend`：重新发送 pending 或 expired 邀请，刷新过期时间并触发邀请通知。
- `notification.list`、`notification.invitation.accept`、`notification.invitation.reject`：被邀请用户在全局通知面板中处理邀请，处理逻辑与 `/invite/[id]` 共享。
- `org.department.member.remove`：将组织成员从部门移除，不影响其组织成员身份，可选。
- `org.member.updateRole`：校验权限后更新 member.role。
- `org.member.addExistingOrCreate`：平台超级管理员将用户加入当前公司；如果邮箱对应用户已存在，则创建 member；如果用户不存在，则先创建平台账号再创建 member；可选写入初始部门归属。
- `org.member.remove`：移除 member，禁止移除最后 owner；移除前同步删除其部门成员关系。
- `org.session.list`：读取当前公司范围内成员会话，只返回必要设备、IP、最近活跃时间和风险状态，并支持按部门筛选。
- `org.session.revoke`：校验 owner/admin 或平台管理员权限后撤销成员会话。
- `org.update`：校验 owner/admin 权限后更新 organization。
- `org.uploadLogo` 或受控上传接口：校验 owner/admin 或平台管理员权限后上传组织 Logo，只允许图片 MIME 类型，成功后返回 URL 或对象引用，再由组织设置保存流程写入 `auth_organization.logo`。
- `org.delete`：校验 owner 或平台超级管理员权限，二次确认后删除组织。

### 组织风险与安全状态数据口径

组织页中所有“异常”“风险”“安全状态”必须由服务端统一计算，不能在部门树、成员表格、概览卡片或登录情况页中写死 `0` 或 `normal`。

第一版风险来源：

- `system_request_log`：
  - 统计当前组织成员最近 30 天的请求日志。
  - `risk_level='high'` 视为高风险。
  - `risk_level='medium'` 可在详情中展示原因，但部门树第一版只用高风险计数，避免过度告警。
  - 请求日志中的 `user_id`、`organization_id`、`created_at`、`risk_level`、`risk_reasons` 用于关联成员、部门和组织。
- `auth_session`：
  - 统计当前组织成员未过期会话。
  - 同一成员活跃会话数超过 5 个，标记该成员存在会话风险。
  - 未记录 IP 或 User-Agent 的活跃会话标记为中风险，仅在成员详情或登录情况中展示，不纳入部门树高风险计数。
  - 会话存在 30 天以上且最近 30 天没有活跃更新时间时，标记为长期会话风险。
- `system_api_key_usage_log`：
  - 组织级 API Key 最近 7 天失败率超过 20%、存在 5xx、429 激增或失败原因属于高危时，进入组织治理行动队列，不直接计入部门成员风险。

节点风险计算：

- 公司根节点 `riskCount`：最近 30 天存在高风险请求、超量活跃会话或长期会话风险的去重成员数。
- 部门节点 `riskCount`：该部门成员范围内满足上述风险条件的去重成员数。
- 没有风险数据时返回真实 `0`；但该 `0` 必须来自计算结果，不允许作为占位常量。
- 部门树默认展开公司根节点和 `riskCount > 0` 的分支。

成员安全状态：

- `normal`：最近 30 天无高风险请求，活跃会话数未超过阈值，无长期会话风险。
- `risk`：最近 30 天存在高风险请求、活跃会话数超过阈值或长期会话风险。
- 筛选 `securityStatus=risk` 时，服务端必须按上述规则过滤；不能先返回全部成员再在前端模拟筛选。

组织概览风险数据：

- `riskySessionCount`：当前组织成员中满足会话风险规则的未过期会话数。
- “最近组织事件”来自 `system_request_log`、`auth_invitation`、`auth_member.created_at`、`system_organization_department.created_at` 和组织级 API Key 使用日志；无事件时显示空态，不使用固定文案。
- 成员增长图表保持使用 `auth_member.created_at` 最近 6 个月累计值；没有成员时展示 0 值趋势。

登录情况页数据处理：

- `org.session.list` 返回成员、部门、设备、浏览器、完整 IP、User-Agent 摘要、创建时间、最近活跃时间、风险等级和风险原因。
- 完整 User-Agent 仅在详情或展开区域展示；列表默认展示摘要，避免表格过宽。
- 撤销会话后重新计算部门树风险、组织概览风险和登录情况列表。

## 实现要点

- 仅启用组织、成员、邀请和活跃组织能力；不提供额外分组管理入口。
- Better Auth organization 只表示公司；部门不是 organization，不拥有 slug，不影响 activeOrganizationId。
- 部门树需要产品层字段，例如 `organizationId`、`parentDepartmentId`、`name`、`path`、`depth`、`sortOrder`、`status`、`managerUserId`、`description`、`createdBy`、`updatedBy`、`deletedAt` 和 `deletedBy`。
- 部门创建必须写入 `system_organization_department`，`path` 使用父级 path 拼接新部门 id，`depth` 为父级 depth + 1，`status` 初始为 `active`。
- 部门重命名只更新部门 `name`，不改变组织 slug、activeOrganizationId 或成员组织身份。
- 部门删除第一版采用保守策略：存在子部门或部门成员时禁止删除，并在确认弹窗和错误 toast 中提示先迁移或移除归属；删除通过 `deletedAt`、`deletedBy` 软删除标记完成。
- 成员属于 organization；部门归属通过产品扩展表 `system_organization_department_member` 表达。该表使用公共审计和软删除字段，用户接受邀请后先成为组织成员，再按邀请中的默认部门建立部门成员关系。
- 创建部门、重命名部门、删除部门和创建部门成员归属时，产品扩展表必须写入当前登录用户到 `createdBy`、`updatedBy`、`deletedBy` 等审计字段；Better Auth 自有 member 表仍保持插件原有字段语义。
- 部门、部门成员归属的列表、详情、统计、搜索、邀请关联展示和风险聚合默认只查询 `deletedAt is null` 的记录；已软删除数据仅供后续审计或恢复能力使用。
- 第一版成员分配部门仅处理「未分配 -> 单个部门」；跨部门调动、一个成员多部门归属和批量分配后续单独设计。
- 成员、邀请和会话查询必须明确作用于公司整体还是某个部门节点。
- 部门树 UI 第一版可基于 shadcn/ui `Collapsible`、`ScrollArea`、`Button` 和 `Badge` 自组；如引入第三方 registry TreeView，必须先评估依赖、可访问性、键盘导航和代码可维护性。
- 组织 owner/admin 默认可管理当前公司及其部门架构。
- 平台管理员进入同一路由时可获得额外平台级操作，例如删除、停用或跨组织移动。
- 不能降级或移除最后一个 owner。
- 邀请接受、拒绝和过期判断遵循 Better Auth organization plugin 语义：只有邀请邮箱对应的登录用户可以接受或拒绝；未验证邮箱时按 Better Auth 配置要求提示先验证邮箱；邀请过期后不能接受，可由组织管理员取消或重新发送。
- 成员表格最大高度固定，超出后在表格区域内滚动；分页按钮即使只有一页也展示禁用态。
- 删除组织前要求输入 slug，并明确对部门、成员、邀请和会话的影响。
- 删除当前活跃组织后跳转 `/dashboard` 并清理 activeOrganizationId。

## 公共组件使用

- 组织成员、邀请和登录情况的桌面表格使用 `src/components/data-table.tsx` 的共享 `DataTable`，页面负责定义业务列、风险 badge、行内图标操作和移动端卡片列表。
- 组织成员、邀请和登录情况的分页控件使用 `src/components/data-pagination.tsx` 的共享 `DataPagination`，页面负责维护 `page`、`pageSize`、搜索和筛选状态。
- 部门树、组织设置表单、邀请弹窗、成员分配弹窗和危险操作确认属于页面业务组件，不放入公共组件。
- 组织 Logo 上传使用平台文件存储配置，相关 provider、路径、S3 凭据和上传测试由 `18-dashboard-admin-platform-settings.md` 统一管理。

## 验收标准

- 五个 tab 路由均可刷新、分享并保持正确选中态。
- tab 顺序为「概览」「组织架构」「邀请」「登录情况」「设置」。
- 五个 tab 必须各自提供匹配页面布局的 loading 骨架；组织架构、邀请、登录情况和设置不得复用概览骨架。
- 内容区不展示额外页面标题、子标题或大号概览横幅。
- 「添加部门」只在组织架构 tab 以图标按钮展示。
- 「邀请成员」只在邀请 tab 以图标按钮展示。
- 当前组织入口位于 Sidebar 的账号设置分组内。
- 组织架构页左栏必须使用紧凑、可展开/折叠的部门树节点 UI，不使用大卡片列表加缩进模拟。
- 组织架构页桌面端左栏约占内容区 `1/3`，右栏约占内容区 `2/3`，右侧成员区不得被压缩成窄表格。
- 部门树节点必须支持右键菜单；重命名和删除入口不应常驻占用树节点行宽。
- 删除部门必须二次确认；存在子部门或部门成员时第一版禁止删除并提示原因。
- 组织架构页的添加部门入口必须放在组织结构卡片标题行最右侧，不放在顶部 tab 工具条。
- 添加部门入口必须打开真实弹窗并调用 `org.department.create`；不允许保留“接口联调后启用”等占位 toast。
- 添加部门成功后新节点必须出现在部门树中，且树列表、组织概览统计和平台组织管理统计在刷新后保持一致。
- 组织架构页未选中部门节点时展示图片占位符空状态。
- 组织架构页选中部门节点后展示该节点成员列表、加入时间和最后登录时间。
- 组织架构页未分配成员可通过操作列分配到部门，成功后成员列表和部门树统计刷新。
- 组织架构页可移除成员，必须二次确认，且不能移除最后一个 owner。
- 右侧成员区行内操作必须使用图标按钮，并提供 tooltip 或 `aria-label`。
- 平台超级管理员可在组织架构页新增用户到当前公司，支持添加已有平台用户和创建新平台账号两种路径。
- 邀请页的邀请成员入口必须放在搜索筛选卡片最右侧，不放在顶部 tab 工具条。
- 邀请成员必须形成完整闭环：管理员发送邀请、被邀请人可获知邀请、被邀请人可接受或拒绝、管理员表格状态随之变化。
- 移动端 tab 切换必须使用下拉菜单，不使用横向滚动 tab。
- 设置页组织信息必须是表单结构，危险区域必须由带说明的按钮操作组成。
- 邀请、登录情况和设置均使用独立路由，不使用 query tab。
- 页面不出现额外分组管理概念。
- 页面在未授权、加载、空数据、错误、成功状态下均有明确反馈。
- 所有敏感动作必须在服务端重新校验 session 和权限。
- 表单字段均有客户端和服务端校验。
- 高危操作必须二次确认。
